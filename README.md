# NLP Text Summarizer

A full-stack web application around an extractive NLP text-summarization
engine. Users register, log in, paste text into a dashboard, and get a
summary generated by a hybrid **NLTK + spaCy** scoring pipeline — along with
an optional detailed breakdown of the sentences, tokens, POS tags, named
entities, and sentence scores behind the summary.

## Description

The summarization logic is unchanged from the original `textsummary.py`
script (see [What changed vs. the original script](#what-changed-vs-the-original-script)).
It is an **extractive** summarizer: it never generates new sentences, only
selects and reorders the most important sentences already present in the
input text, using a hybrid score combining:

- Normalized word frequency
- NLTK part-of-speech weighting
- spaCy part-of-speech weighting
- NLTK named-entity weighting
- spaCy named-entity weighting
- Sentence position (first/second/last sentences are favored)
- Sentence length (very short or very long sentences are penalized)

## Features

- Landing page, registration, login, and an authenticated dashboard
- SQLite-backed accounts with bcrypt-hashed passwords
- Token-based sessions (`Authorization: Bearer <token>`)
- Original text (left) / generated summary (right) side-by-side layout
- Live word/character counts, adjustable summary length, copy & download
- Collapsible "View NLP Analysis" panel: NLTK vs. spaCy sentences, tokens,
  POS tags, named entities, and per-sentence scores
- Friendly error handling everywhere (no raw Python tracebacks reach the UI)
- Responsive design (desktop / tablet / mobile)

## Technologies used

**Backend:** Python, FastAPI, Uvicorn, NLTK, spaCy (`en_core_web_sm`),
Pydantic, SQLite, bcrypt

**Frontend:** HTML5, CSS3 (vanilla, no framework), vanilla JavaScript
(Fetch API)

## Installation

### 1. Backend

```bash
cd NLP_Text_Summarizer_Website/backend
python -m venv venv
source venv/bin/activate            # Windows: venv\Scripts\activate

pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

The first time you start the server, it will also automatically download the
NLTK resources it needs (`punkt`, `punkt_tab`, `stopwords`,
`averaged_perceptron_tagger_eng`, `maxent_ne_chunker`,
`maxent_ne_chunker_tab`, `words`). This requires an internet connection the
first time only.

### 2. Frontend

No build step or package manager needed — it's plain HTML/CSS/JS.

## How to start FastAPI (backend)

```bash
cd backend
uvicorn app:app --reload --port 8000
```

- API base URL: `http://127.0.0.1:8000`
- Interactive API docs (Swagger UI): `http://127.0.0.1:8000/docs`

## How to open the frontend

Open `frontend/index.html` directly in a browser, or serve the folder so
relative paths behave consistently:

```bash
cd frontend
python -m http.server 5500
```

Then visit `http://127.0.0.1:5500`.

If your backend runs on a different host/port, update `API_BASE_URL` in
`frontend/js/config.js`.

## API endpoints

| Method | Endpoint          | Auth required | Description                              |
|--------|-------------------|:--------------:|-------------------------------------------|
| GET    | `/api/health`     | No             | Liveness check.                           |
| POST   | `/api/register`   | No             | Create an account.                        |
| POST   | `/api/login`      | No             | Log in, returns a session token.          |
| POST   | `/api/logout`     | No             | Invalidates the given session token.      |
| GET    | `/api/me`         | Yes            | Returns the current logged-in user.       |
| POST   | `/api/summarize`  | Yes            | Runs the NLP summarizer on submitted text.|

### `POST /api/summarize`

Request:

```json
{
  "text": "user entered text",
  "summary_ratio": 0.30
}
```

Response:

```json
{
  "summary": "...",
  "nltk_sentences": [],
  "spacy_sentences": [],
  "nltk_tokens": [],
  "spacy_tokens": [],
  "nltk_pos": [],
  "spacy_pos": [],
  "nltk_entities": [],
  "spacy_entities": [],
  "sentence_scores": {},
  "error": null
}
```

## How authentication works

1. `POST /api/register` stores the user in SQLite (`users.db`) with a
   **bcrypt hash** of the password — never the plain text.
2. `POST /api/login` verifies the password against the stored hash and, on
   success, generates a random session token stored in a `sessions` table
   (24-hour expiry) and returns it to the client.
3. The frontend stores the token in `localStorage` and sends it as
   `Authorization: Bearer <token>` on every request to a protected endpoint.
4. `dashboard.html` checks for a stored token on load and redirects to
   `login.html` if none is found.
5. `POST /api/logout` deletes the session token server-side; the frontend
   also clears its local copy.

## How text summarization works

1. The frontend sends the original text (and a summary-length ratio) to
   `POST /api/summarize` with the session token attached.
2. The backend validates the request, then calls `summarizer()` in
   `summarizer.py`.
3. The text is tokenized and tagged by both NLTK and spaCy; each sentence is
   scored with the hybrid formula described above.
4. The top-scoring sentences (proportional to `summary_ratio`) are selected
   and restored to their original order to form the final summary.
5. The full NLP breakdown (tokens, POS tags, entities, sentence scores) is
   returned alongside the summary and rendered in the dashboard's
   "View NLP Analysis" panel.

## Example usage

1. Register an account on `register.html`.
2. Log in on `login.html`.
3. On the dashboard, paste an article or report into **Original Text**.
4. Pick a summary length (Short / Balanced / Detailed) and click
   **Summarize Text**.
5. Read the summary on the right, copy it or download it as `summary.txt`.
6. Optionally expand **View NLP Analysis** to inspect the NLTK/spaCy
   tokens, POS tags, named entities, and sentence scores behind the result.

## What changed vs. the original `textsummary.py`

The summarization **algorithm itself is untouched** — same scoring weights,
same formula, same sentence-selection logic. What changed is purely
structural, to turn a standalone script into a reusable backend module:

- Removed the hard-coded sample `text` variable and the "run on import"
  block at the bottom of the script — the API now supplies user text
  instead of a fixed example.
- Wrapped the spaCy model load in `get_spacy_model()` so a missing model
  raises a clear, catchable `SpacyModelMissingError` (with the install
  command) instead of crashing the process.
- Added `initialize_nlp_engine()`, called once at FastAPI startup, so NLTK
  resources and the spaCy model are loaded up front rather than on the
  first request.
- Added a couple of defensive guards (e.g. empty input, text with zero
  spaCy sentences after cleaning) that return a friendly `error` message
  instead of raising.

## Troubleshooting

**`SpacyModelMissingError` / "spaCy model 'en_core_web_sm' is not installed"**
Run `python -m spacy download en_core_web_sm` inside your backend virtual
environment.

**Frontend shows "Could not reach the server. Is the backend running?"**
Make sure `uvicorn app:app --reload --port 8000` is running, and that
`frontend/js/config.js` points at the correct host/port.

**CORS errors in the browser console**
The backend allows all origins by default for local development
(`CORSMiddleware(allow_origins=["*"])`). If you've changed that, make sure
the frontend's origin is included.

**"Text is too short to summarize"**
The API requires at least 20 characters of input — this is a basic guard
against near-empty submissions.

**Login works but `/api/summarize` returns 401**
Session tokens expire after 24 hours. Log out and back in to get a fresh
token.
